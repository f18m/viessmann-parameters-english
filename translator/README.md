# Viessmann Parameter Translator

My approach to translation consists in a small Python script to automate the translation of the thousands of parameters documented in the "Sources" repositories.

The translator uses a mix of static dictionaries and [Google Cloud Translation](https://cloud.google.com/translate) (v3 by default when a project is set, with v2 fallback) or [DeepL API interface](https://www.deepl.com/it/translator) to achieve semi-automated translation.

Each `just translate` run takes about 7 minutes.

## Files

- `Viessmann.Parameter.Adresses.xlsx` : default input Excel workbook (German parameters)
- `Viessmann_Parameter_Adresses_EN_translated.xlsx` : default translated output workbook
- `viessmann_translate.py` : translator script
- `dictionary.json`        : technical German -> English overrides
- `translation_review.csv` : unique tokens to review/correct (`EnglishTranslation` column)
- `untranslated_tokens.csv`: tokens that remained unchanged after translation (generated by `just translate` or `just report`)
- `justfile`               : task runner recipes for venv setup, `gcloud` configuration, and translation
- `README.md`              : this guide

## `translation_review.csv` format

`translation_review.csv` is a UTF-8 CSV file with the following header and columns:

```csv
GermanToken,EnglishTranslation,KeepOriginal,Notes
01Freigabe,,,
GueltSollleistung,ValidSetpointPower,,abbreviated German compound
```

- `GermanToken`: A single underscore-separated token extracted from parameter names (excluding `~0x...` hex suffixes).
- `EnglishTranslation`: The English replacement to use. Rows with a non-empty `EnglishTranslation` override both `dictionary.json` and the translation API; rows where it is blank are ignored and fall back to `dictionary.json` or the selected API provider.
- `KeepOriginal`: Set to `true` / `yes` / `1` to preserve `GermanToken` verbatim without translating it and omit it from `untranslated_tokens.csv`.
- `Notes`: Optional free-text notes (ignored by the script).

## Recommended workflow (using `just`)

1. Open `translation_review.csv` in Excel/LibreOffice and fill `EnglishTranslation` for technical terms where you want a specific Viessmann-style translation.
2. Put additional permanent overrides in `dictionary.json`.
3. Create the `.venv` and install dependencies (`openpyxl`, `google-cloud-translate`):

    ```sh
    just setup
    ```

4. Authenticate Google Cloud Application Default Credentials (if not already done), configure the project/quota project, and enable the Cloud Translation API:

    ```sh
    just gcloud-auth
    just gcloud-configure
    just gcloud-status
    ```

5. Run the translation with Google Cloud Translation v3 (outputs `Viessmann_Parameter_Adresses_EN_translated.xlsx` and `untranslated_tokens.csv`):

    ```sh
    just translate
    ```

To inspect which tokens remained untranslated without calling the API again:

    ```sh
    just report
    ```

For a dry/local test using only static dictionaries without calling an external API:

    ```sh
    just dry-run
    ```

To list all available `just` recipes:

    ```sh
    just --list
    ```

You can also run `.venv/bin/python viessmann_translate.py` directly to customize flags such as `--input`, `--output`, `--provider {none,google,google-v2,google-v3,deepl}`, `--project`, or `--location`.

The program preserves hexadecimal addresses such as `~0xB490` and obvious
technical identifiers such as `WPR3`, `HK2`, `KK2`, etc.
